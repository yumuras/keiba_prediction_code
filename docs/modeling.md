# モデリングのコード解説

[src/train.py](../src/train.py) のうち、モデルを作って評価する部分の解説です。
処理は次の順に進みます。

```
load()           CSVを読み、目的変数と基本の列を作る
  ↓
add_features()   過去成績・騎手/調教師成績・レース内の相対値を作る
  ↓
walk_forward()   月ごとに「それより前のデータで学習 → その月を予測」を繰り返す
  └ Top3Model    1段目: 能力モデル → 2段目: オッズと組み合わせ → レース内で正規化
  ↓
main()           AUC・LogLoss と、馬券を買った場合の成績を表示
```

## 1. データの読み込み `load()`

```python
df = pd.concat([pd.read_csv(p, ...) for p in paths], ignore_index=True)   # 2024〜2026年のCSVをつなげる
df["race_id"] = df["date"].dt.year.astype(str) + "_" + df["race_id"]
```

PDFに書かれているレースIDは年ごとの通し番号で、年をまたぐと同じ番号が出てきます（2025年と2026年で2,489件、2024年と2025年で3,071件重複）。
同じIDのレースが混ざると、「レース内の合計」や「レース内のzスコア」が別のレースを巻き込んで狂うので、読み込み時に年を付けて一意にしています。

```python
df["top3"] = (df["finish"] <= 3).astype(int)
```

**目的変数**は「3着以内なら1」です。競走中止の馬は `finish` が空欄（NaN）なので、比較結果は False になり0になります。

```python
inv = 1 / df["odds"]
df["mkt_prob"] = inv / inv.groupby(df["race_id"]).transform("sum")
```

**市場の勝率**です。単勝オッズの逆数（1/オッズ）は、その馬が勝つ確率の市場の見積もりです。
ただしJRAは売上の一部を差し引いてから払い戻すため、1レース分を合計すると1を超えます（このデータでは平均1.27）。
そこで、レース内の合計で割って合計を1にそろえています。`groupby("race_id").transform("sum")` は「各行に、その行が属するレースの合計」を並べる書き方です。

```python
df["behind"] = (df["time_sec"] - df["race_id"].map(win_time)).clip(upper=5)
```

**勝ち馬とのタイム差（秒）**です。着順だけでは「僅差の4着」と「大差の4着」を区別できないので追加しました。
大敗した1レースの影響が大きくなりすぎないよう、5秒で頭打ちにしています。
これはレース結果なので、このレースの特徴量ではなく、**次のレース以降の「前走の成績」**としてだけ使います。

```python
parts = df["course"].str.split("・")
df["turn"] = parts.apply(lambda p: next((x for x in p if x in ("右", "左", "直線")), "不明"))
df["inout"] = parts.apply(lambda p: next((x for x in p if x in ("外", "外内")), "内"))
```

**コースの形**です。CSVの `course`（例「芝・右・外」）を「・」で分け、回り（右/左/直線）と内回り/外回りの2列にしています。

```python
first = corners.bfill(axis=1).iloc[:, 0]                       # 最初に記録されたコーナーの順位
df["early_pos"] = (first - 1) / (df["num_runners"] - 1)       # 0 = 先頭、1 = 最後方
df["gain"] = (df["corner4"] - df["finish"]) / df["num_runners"]  # 最終コーナーから何頭抜いたか
```

**位置取り**です。PDFの「コーナー通過順位」から変換時に読み取った `corner1`〜`corner4` を使います。
頭数が違うレースでも比べられるよう、順位を 0（先頭）〜1（最後方）に直しています。
`bfill(axis=1)` は「右側の列の値で空欄を埋める」操作で、3・4コーナーしかないコースでは `corner3` が最初の値になります。
これもレース結果なので、次の「2-4. 脚質」で前走までの値としてだけ使います。

```python
df["hour"] = df["start_time"].str[:2].astype(int)
df = df.merge(w[["venue", "date", "hour", "temp", "humidity", ...]], on=["venue", "date", "hour"], how="left")
```

**気象**です。`scripts/fetch_weather.py` で取得した気象庁の1時間ごとの値を、競馬場・日付・時（発走時刻の時の部分）で結合します。
15:30発走なら15時の観測値（14時〜15時の値）を使います。`precip_day` はその日の1時から発走までの降水量の合計です。

## 2. 特徴量づくり `add_features()`

### 2-1. 騎手・調教師の成績 `prior_stats()`

```python
daily[f"{prefix}_runs"] = g["n"].cumsum() - daily["n"]
prev_s = g["s"].cumsum() - daily["s"]
```

騎手（調教師）ごと・日ごとに騎乗数と3着内の数を集計し、累積和から**当日分を引いて**います。
これで「その日より前」の成績だけになります。当日分を含めると、同じ日の他のレースの結果が混ざってしまいます（リーク）。

```python
prior, k = df["top3"].mean(), 20
daily[f"{prefix}_top3_rate"] = (prev_s + prior * k) / (daily[f"{prefix}_runs"] + k)
```

**平滑化**です。騎乗数が少ない騎手は、2騎乗2回3着内なら100%のように極端な値になります。
そこで「全体平均の成績で20騎乗した」という仮のデータを足しています。騎乗数が少ないうちは全体平均に近く、増えるほど本人の成績に近づきます。

同じ関数を、騎手名と芝/ダート/障害をつないだキー（`jockey_surface`、例：`川田将雅_ダート`）にも使い、騎手のコース種別ごとの成績（`jockey_surf_top3_rate`）も作っています。

**相性**も同じ関数で作っています。キーを2つの名前をつないだものにするだけです。

| キー | 意味 | 平滑化 |
|---|---|---|
| `horse_jockey`（例 `ゲルチュタール_坂井瑠星`） | 馬と騎手のコンビの成績 | `k=5`。コンビの回数は少ないので、弱めにして本人たちの成績が出やすくする |
| `jockey_trainer` | 騎手と調教師（厩舎）の組み合わせの成績 | `k=20` |

馬と調教師の組み合わせは作っていません。1頭の馬はほぼ同じ厩舎に所属し続けるので、その馬自身の成績と同じになるためです。

### 2-2. 馬の過去成績

```python
df = df.sort_values(["horse_name", "date"])
g = df.groupby("horse_name")
past_mean = lambda s: s.shift(1).expanding().mean()
df["prev_behind"] = g["behind"].shift(1)
df["mean_behind"] = g["behind"].transform(past_mean)
```

馬ごとに日付順に並べ、`shift(1)` で1行ずらすのがポイントです。
`shift(1)` は「1つ前の行の値」、つまり**前走の値**を取り出します。`shift(1).expanding().mean()` は「前走までの平均」です。
こうすることで、そのレース自身の結果は特徴量に入りません。

| 列 | 意味 |
|---|---|
| `horse_runs` | データ内での過去の出走数 |
| `horse_prev_finish_rate` / `horse_mean_finish_rate` | 前走／過去平均の着順率（着順÷頭数。0に近いほど上位） |
| `prev_behind` / `mean_behind` | 前走／過去平均の勝ち馬とのタイム差 |
| `prev_mkt_prob` | 前走の市場の勝率。前走でどれだけ期待されていたか |
| `prev_same_surface` | 前走と同じ芝/ダートか |
| `prev_dist_diff` | 前走からの距離の変化（延長ならプラス） |
| `days_since_last` | 前走からの間隔（日） |
| `horse_top3_rate` | 過去の3着内率。出走数が少ない馬は、騎手と同じ考え方で全体平均（0.2）寄りに平滑化 |
| `best_finish_rate` | 過去の最高の着順率 |
| `mean_mkt_prob` | 過去の市場の勝率の平均。これまで市場からどれだけ評価されてきたか |
| `prev_class_diff` | 前走からのクラスの変化。`CLASS_RANK` でクラスを数値（未勝利0〜GⅠ7）にし、その差を取る。昇級ならプラス |
| `jockey_change` | 前走から騎手が替わったか（乗り替わり） |
| `carried_weight_diff` | 前走からの斤量の増減 |
| `surface_mean_finish_rate` | 同じ芝/ダートでの過去平均着順率（`groupby(["horse_name", "surface"])` で芝とダートを分けて計算） |
| `venue_runs` | 同じ競馬場での過去の出走数 |

初出走の馬はこれらが空欄（NaN）になります。後述の勾配ブースティングは空欄をそのまま扱えるので、埋める必要はありません。

### 2-4. 脚質

```python
df["prev_early_pos"] = g["early_pos"].shift(1)
df["mean_early_pos"] = g["early_pos"].transform(past_mean)
df["front_rate"] = g["is_front"].transform(past_mean)
df["n_front_runners"] = (df["mean_early_pos"] < 0.25).groupby(df["race_id"]).transform("sum")
```

1章で作った位置取りを、馬の過去成績と同じ `shift(1)` の方法で「前走まで」の値にしています。

| 列 | 意味 |
|---|---|
| `prev_early_pos` / `mean_early_pos` | 前走／過去平均の序盤の位置。小さいほど先行・逃げタイプ、大きいほど差し・追込タイプ |
| `front_rate` | 過去に逃げた（最初のコーナーを先頭で通過した）割合 |
| `mean_last_corner_pos` | 過去平均の最終コーナーの位置 |
| `mean_gain` | 過去平均で、最終コーナーからゴールまでに抜いた頭数（頭数で割った値） |
| `n_front_runners` | このレースに出る馬のうち、過去平均で前から1/4以内にいる先行タイプの頭数。多いとペースが速くなりやすい |

> **脚質がほとんど効かなかった理由**
> 過去の序盤の位置は、単独では3着以内を予測できます（AUC 0.60）。ただ、先行できる馬はもともと強い馬が多く、過去の着順や市場評価（単独AUC 0.71）と情報が重なっています。
> そのため、モデルに足しても精度はほぼ変わりませんでした。コースごとの先行有利度との組み合わせも試しましたが、改善しませんでした。

### 2-5. 道悪適性

```python
def past_mean_when(col, cond):
    v = df[col].where(cond == 1)                       # 条件に合うレースだけ値を残す（他は空欄）
    prev_sum = v.fillna(0).groupby(df["horse_name"]).cumsum() - v.fillna(0)
    prev_n = v.notna().astype(int).groupby(df["horse_name"]).cumsum() - v.notna().astype(int)
    return prev_sum / prev_n.replace(0, np.nan), prev_n
```

「道悪のレースだけの、前走までの平均」を計算する関数です。
`where(cond == 1)` で道悪でないレースの値を空欄にし、馬ごとの累積和と累積回数から**今回の分を引いて**平均を出しています（騎手の成績と同じ考え方）。
`groupby(...).transform(past_mean)` で「道悪のレースだけ」を対象にすると、良馬場の日の行には良馬場どうしの平均しか入りません。
この方法なら、良馬場の日の行にも「その馬の道悪での過去平均」を入れられます。

| 列 | 意味 |
|---|---|
| `wet_runs` | 過去に道悪（稍重・重・不良）を走った回数 |
| `wet_mean_finish_rate` / `dry_mean_finish_rate` | 道悪／良馬場での過去平均着順率 |
| `wet_diff` | 上の2つの差。プラスなら道悪で着順が悪くなるタイプ |
| `wet_behind_diff` | 勝ち馬とのタイム差で見た、道悪での成績の落ち幅 |
| `wet_fit_today` | 今日が道悪なら `wet_diff`、良馬場なら0。今日の馬場と適性の組み合わせを明示する |
| `cond_mean_finish_rate` | 今日と同じ条件（芝/ダート × 道悪/良）での過去平均着順率。レース内のzスコアも作る |

> **道悪適性が効かなかった理由**
> 道悪のレースに出る馬のうち、道悪と良馬場の両方を走った経験がある馬は35%で、道悪の経験回数も中央値1回です。
> 1〜2回の成績では、適性なのか、その日の調子や展開なのか区別できません。
> 2025〜2024年のデータを加えて経験のある馬が66%に増えても、精度は変わりませんでした（一つ外した場合のAUC差は±0.0001以内）。血統から補う方法を試す価値があります。

### 2-3. レース内の相対値（zスコア）

```python
for c in RELATIVE:
    gr = df.groupby("race_id")[c]
    df[f"{c}_z"] = (df[c] - gr.transform("mean")) / gr.transform("std")
```

競馬は**同じレースの馬との比較**で決まります。騎手の3着内率が30%でも、他の馬の騎手が全員40%なら不利です。
そこで、レース内の平均を引いて標準偏差で割り、「このレースの中でどれくらい上か」を表す値（zスコア）を作っています。
改良後の重要度では、`jockey_top3_rate_z`（騎手の相対的な強さ）が一番効いていました。

## 3. モデル `Top3Model`

### 3-1. 1段目: 能力モデル `ability_model()`

```python
HistGradientBoostingClassifier(
    categorical_features="from_dtype", max_iter=300, learning_rate=0.03,
    max_leaf_nodes=7, min_samples_leaf=80, l2_regularization=1.0,
    early_stopping=True, validation_fraction=0.2, random_state=42,
)
```

**勾配ブースティング**は、小さな決定木を少しずつ足していき、前の木が外した分を次の木が補正していく手法です。
オッズを使わない特徴量（`FEATURES`、77個）だけで3着内確率を予測します。

| 引数 | 意味と、この値にした理由 |
|---|---|
| `categorical_features="from_dtype"` | category型の列（芝/ダート、クラスなど）をカテゴリとして扱う |
| `learning_rate=0.03` | 1本の木の影響の大きさ。小さいほど慎重に学習する |
| `max_leaf_nodes=7` | 1本の木の葉の数。少ないほど単純な木になる |
| `min_samples_leaf=80` | 1つの葉に最低80頭必要。少数の馬にだけ当てはまるルールを作らせない |
| `l2_regularization=1.0` | 葉の値が極端にならないようにする正則化 |
| `early_stopping=True` | 学習データの20%を検証用に取り分け、改善しなくなったら木を足すのをやめる |

木を浅く・葉を大きく・学習率を小さくして**過学習**を抑えています。
全場のデータ（約3.5万頭）に増やした後も、葉の数を15・31に増やした設定より、この設定の方が評価データの成績が良い結果でした。
改良前（`max_leaf_nodes=15, min_samples_leaf=40, learning_rate=0.05`）より、評価データのAUCが上がりました。

### 3-2. 2段目: オッズとの組み合わせ（`use_odds=True` のとき）

```python
def _stack_X(self, d, p_ability):
    return pd.DataFrame({
        "log_mkt_prob": np.log(d["mkt_prob"]),
        "ability_logit": logit(p_ability),
        "log_runners": np.log(d["num_runners"]),
    })
```

1段目の予測と市場の勝率を**ロジスティック回帰**で組み合わせます。入力は3つです。

- `log_mkt_prob`: 市場の勝率の対数
- `ability_logit`: 能力モデルの予測確率を対数オッズ（logit = log(p / (1-p))）にしたもの
- `log_runners`: 頭数の対数。頭数が多いほど3着以内に入りにくいことを補正する

ロジスティック回帰は、入力に係数をかけて足し、確率に変換するモデルです。学習した係数を見れば、**それぞれの情報をどれだけ信用しているか**が分かります。

> **なぜ勾配ブースティングにオッズを直接入れないのか**
> 改良前はオッズも勾配ブースティングの特徴量に入れていましたが、オッズだけのロジスティック回帰に負けていました（京都のみのデータで AUC 0.806 対 0.822）。
> 決定木は値を「〇〇倍以下か」で区切って階段状に予測するため、オッズのように滑らかに効く値を少ないデータで学ぶのが苦手です。
> オッズは対数を取ると3着内率とほぼ直線の関係になるので、ロジスティック回帰の方が向いています。

### 3-3. out-of-fold 予測（2段目を正しく学習するための工夫）

```python
oof = np.zeros(len(train))
for tr_idx, va_idx in GroupKFold(5).split(train, groups=train["race_id"]):
    m = ability_model().fit(train.iloc[tr_idx][FEATURES], train.iloc[tr_idx]["top3"])
    oof[va_idx] = m.predict_proba(train.iloc[va_idx][FEATURES])[:, 1]
self.stacker = LogisticRegression().fit(self._stack_X(train, oof), train["top3"])
```

2段目の学習には、1段目の予測が必要です。しかし、1段目が学習に使ったデータを予測させると、答えを知っているので**実際より良く当たって見えます**。
それをそのまま2段目に渡すと、2段目は「能力モデルはよく当たる」と思い込み、重みを大きくしすぎてしまいます。

そこで学習データを5つに分けます。4つで1段目を学習し、残り1つを予測する、という作業を5回繰り返します。
こうして、全レースについて「1段目が見ていないときの予測」（out-of-fold 予測）を作り、それで2段目を学習しています。
`GroupKFold` で**レース単位**に分けているのは、同じレースの馬が学習側と予測側に分かれないようにするためです。

### 3-4. レース内の正規化 `normalize_in_race()`

```python
n_top3 = np.minimum(3, レースの頭数)
return p / レース内の p の合計 * n_top3
```

3着以内に入るのは各レースでちょうど3頭です。しかしモデルは1頭ずつ独立に確率を出すので、レース内の合計は3になりません。
そこで、合計が3になるように一律に拡大・縮小しています。頭数が3頭以下のレースでは、合計を頭数に合わせます。
これで確率として解釈しやすくなり、LogLossも少し良くなります。

## 4. 評価 `walk_forward()`

```python
for m in months:                     # 3月〜9月
    train, test = df[df["month"] < m], df[df["month"] == m]
    model = Top3Model(use_odds).fit(train)
    outs.append(test.assign(prob=model.predict(test)))
```

**ウォークフォワード評価**です。実際に予測するときと同じく、「その時点までのデータで学習し、次を予測する」を月ごとに繰り返します。

- 2026年3月を予測：2024年1月〜2026年2月のデータで学習
- 2026年4月を予測：2024年1月〜2026年3月のデータで学習
- …
- 2026年9月を予測：2024年1月〜2026年8月のデータで学習

データは2024〜2026年の成績CSV（`data/all_*.csv`）を読み込んでつなげています。`df["month"]` は2026年1月を1とした通算の月番号（2025年12月が0、2024年1月が-23）で、この数字で学習と評価を分けます。

1回の分割だけで評価するより、評価するレースが多くなり（全場で1,956レース）、結果のぶれが小さくなります。
ランダムに分割すると、未来のデータで学習して過去を予測することになり、実際より良い成績が出てしまうので使っていません。

### 評価指標

| 指標 | 意味 |
|---|---|
| AUC | 3着以内の馬に、そうでない馬より高い確率を付けられているか（並び順の正しさ）。0.5がでたらめ、1が完璧 |
| LogLoss | 確率の値そのものの正確さ。小さいほど良い。自信を持って外すと大きく悪化する |
| 勝率・複勝率・単勝回収率 | 各レースで予測1位の馬の単勝を100円ずつ買った場合の成績 |

### 比較対象 `market_baseline()`

オッズ（市場の勝率）と頭数だけを入れたロジスティック回帰です。「オッズを見れば分かること」の基準線で、**これを超えられるか**がモデルの実力の目安になります。
今のところ、オッズありのモデルはこの基準線とほぼ同じ精度です。今のデータで分かる情報の多くは、すでにオッズに織り込まれているということです。

---

## 5. 市場（オッズ）と比べた評価 `src/evaluate.py`

AUCやLogLossが高くても、それがオッズから分かる範囲なら、馬券では役に立ちません。
`evaluate.py` は、**オッズと比べてどれだけ良いか**を、信頼区間つきで出します。

### 5-1. 勝ち馬の予測（Benter型）

```python
# P(馬iが勝つ) = softmax_i( a * log(市場の勝率_i) + b * 能力モデルのlogit_i )   （レースの中でソフトマックス）
nll = lambda w: -win_log_likelihood(X @ w, starts, win).mean()
w = minimize(nll, init, method="BFGS").x
```

1頭ずつ独立に確率を出すロジスティック回帰と違い、**同じレースの馬どうしを比べて、勝つのは1頭だけ**という形で学習します（多項ロジット、またはレース内ソフトマックス）。
`a` は「市場をどれだけ信じるか」、`b` は「市場の評価に、能力モデルの見方をどれだけ足すか」です。
`b = 0` の場合が「市場だけ（補正あり）」で、それとの差が、能力モデルの足した分になります。

- **評価**: 勝ち馬に付けた確率の対数（対数尤度）を、1レースあたりで比べます。0に近いほど良く、差が大きいほど改善が大きいです。
- 学習には、能力モデルが「見ていないレース」に出した予測（out-of-fold、3-3節）を使います。`train.fit_with_oof(train, target)` が、モデルとその out-of-fold 予測をまとめて返します。
- **能力モデルを2種類**用意して比べます。目的が「3着以内」のもの（`top3`）と、「勝ち」のもの（`win`）です。同じ `ability_model()`（同じ特徴量・同じ設定）を、目的だけ変えて学習しています。
  - 市場だけ（`b = 0`）
  - 市場 ＋ 3着以内の能力モデル
  - 市場 ＋ 勝ちの能力モデル
  - 市場 ＋ 両方（係数は3つ）
  - 勝ちの能力モデル単独（オッズなし。係数は1つ。市場の代わりになるかを見る）
- 実装の工夫: 同じレースの馬が連続して並んでいる前提で、`np.add.reduceat` を使い、レースごとの合計を一度に計算しています（レースを1つずつ回さないので速い）。

### 5-2. 信頼区間（ブートストラップ）

```python
idx = rng.integers(0, len(x), size=(n_boot, len(x)))   # レースを復元抽出
stats = x[idx].sum(axis=1) / w[idx].sum(axis=1)
return x.sum() / w.sum(), np.percentile(stats, [2.5, 97.5])
```

馬ではなく**レースを単位に**、復元抽出を2,000回繰り返し、改善幅の95%区間を出しています。
同じレースの馬は結果が互いに関係している（1頭が勝てば他は勝てない）ので、馬を単位にすると区間が狭く出すぎてしまいます。
区間が0をまたいでいれば、「市場との差は誤差の範囲」です。

### 5-3. 3着以内の評価

- **LogLoss**: 全頭のLogLossを、レースごとに合計して比べます（市場のモデルとの差を、レース単位でブートストラップ）。
- **レース内AUC**: レースごとにAUCを出して平均します。全頭をまとめたAUCは、頭数の多いレースと少ないレースの違い（頭数が少ないほど3着以内に入りやすい）も拾ってしまうので、馬の優劣だけを見るには、レース内で測る方が正確です。市場のAUCは、全体で0.8206、レース内で0.8005です。

### 5-4. 校正

- **モデル ÷ 市場 の比ごとの複勝率**: 比が1.05〜1.15の馬と、0.85〜0.95の馬で、実際の複勝率が市場の予測からどちらにずれるか。モデルの上乗せが本物なら、ずれる方向と大きさがモデルの予測と合います。
- **期待値（モデルの勝率 × オッズ）ごとの単勝回収率**: 期待値が1を超える馬だけを買えば儲かるはずです。区分ごとの回収率と、その誤差（標準偏差÷√頭数）を並べ、誤差の大きさも見られるようにしています。

### 5-5. 複勝の評価

成績PDFの払戻欄には、複勝の払戻（3着以内に入った馬ごと、100円あたり）が載っています。変換時に `place_payout` として読み取りました。

```python
placed = train[train["place_payout"] > 0]
slope, icpt = np.polyfit(np.log(placed["odds"]), np.log(placed["place_payout"]), 1)
smear = np.exp(np.log(placed["place_payout"]) - (slope * np.log(placed["odds"]) + icpt)).mean()
pay_hat = np.exp(slope * np.log(test["odds"]) + icpt) * smear
```

**予想払戻**です。レースの前には複勝の払戻は分からないので、「3着以内に入ったときの払戻」を、単勝オッズから予想します。
単勝オッズが高い馬ほど払戻も高いので、対数どうしの直線（`np.polyfit`）で結びます。学習データ（評価する月より前）だけで求めます。
`smear` は、対数の世界で直線に当てはめた予想を元の尺度に戻すと、平均が低く出る（対数の平均より、元の値の平均の方が大きい）ことの補正です。

```python
d["ev"] = d["p_top3"] * d["pay_hat"] / 100        # モデルの期待値（1円あたりの期待払戻）
```

**期待値**は、「3着以内に入る確率 × 入ったときの払戻」です。1を超えれば、平均的には買った額より多く戻ってくる計算になります。
市場だけの確率（`p_mkt3`）で同じ計算をした値と比べると、モデルが市場より割安な馬を見つけているかが分かります。

**回収率の誤差**は、勝ち馬の評価と同じく、レースを復元抽出するブートストラップで出しています。同じレースの複数の馬を買うと、結果が互いに関係するためです。

払戻を読み取る際の注意:
- 払戻欄の複勝は、馬番が丸数字の図形で書かれていて読めませんが、払戻額は**着順の並び**（1着、2着、3着）で書かれています。そこで、払戻を着順に対応させています。全レースで確かめると、この対応で「複勝払戻が単勝オッズより高い」逆転が起きた馬は27,897頭中17頭で、馬番の昇順に対応させると2,913頭になるので、着順の並びが正しいと分かります。
- 1着同着のレースは、払戻の表で文字が重なり、読み取れません（14レース）。空欄のままにして、評価から除いています。
